# Engineering notes

Decisions and findings that are not obvious from the code.

## Stack

Vite 7, React 19, TypeScript, Tailwind v4, React Router 6, hosted on Vercel. Animation is CSS plus small React
hooks (IntersectionObserver); no animation library. The project is also edited through Lovable.

## Package manager: Bun, from `bun.lockb`

`bun.lockb` is the only lockfile. Install with:

```bash
bun install --frozen-lockfile
```

`--frozen-lockfile` fails instead of silently re-resolving when `package.json` and the lockfile disagree, so every
install (local, CI, Vercel) gets the same dependency tree. Run scripts with `npm run <script>` or `bun run <script>`.
`bunfig.toml` keeps the binary lockfile format that Lovable maintains. Do not add a `package-lock.json`: Vercel picks
npm over Bun when both files exist.

Node 22.18 or newer is needed locally (the unit tests use Node's built-in TypeScript type stripping).

## Scripts

| Script                    | What it does                                                                        |
| ------------------------- | ----------------------------------------------------------------------------------- |
| `npm run dev`             | Vite dev server                                                                     |
| `npm run build`           | SPA build into `dist/` (also regenerates the MCP function, see below)               |
| `npm run build:prerender` | `build`, then a server render of every sitemap route into `dist/<route>/index.html` |
| `npm test`                | Unit tests (`node:test`, `src/**/*.test.ts`)                                        |
| `npm run test:e2e`        | Builds, then runs the Playwright browser tests in `e2e/` against the built site     |
| `npm run typecheck`       | `tsc --noEmit`                                                                      |
| `npm run lint`            | ESLint                                                                              |
| `npm run sitemap`         | Regenerates `public/sitemap.xml` from content (a unit test fails if it drifts)      |

Browser tests use `playwright-core` (no bundled browser download) and `axe-core`. They look for a Chromium
headless shell in the local Playwright cache, or use `CHROMIUM_PATH`. `BASE_URL=<server>` runs them against any
running server instead of the local build.

## Lint policy

`npm run lint` and `npx prettier --check .` are clean. Nothing is disabled globally; each exception is scoped:

| Scope                             | Exception                                  | Why                                                                                 |
| --------------------------------- | ------------------------------------------ | ----------------------------------------------------------------------------------- |
| `supabase/functions/mcp/index.ts` | Not linted, not formatted                  | Generated bundle, rewritten by `@lovable.dev/mcp-js` on every build                 |
| `src/integrations/supabase/`      | Not formatted (still linted)               | Generated by Lovable's Supabase integration                                         |
| `.lovable/`                       | Not formatted                              | Generated files                                                                     |
| `vercel.json`                     | Not formatted                              | Deployment config                                                                   |
| `src/lib/mcp/`                    | Not formatted (still linted)               | Reformatting changes whitespace in the generated, deployed MCP function             |
| `src/components/ui/**`            | `react-refresh/only-export-components` off | shadcn/ui exports style helpers (e.g. `buttonVariants`) beside components; dev only |

## MCP endpoint

`src/lib/mcp/` is the source of the public MCP server. On every Vite build, the Lovable plugin
(`@lovable.dev/mcp-js`) bundles `src/lib/mcp/index.ts` with esbuild into one Deno module at
`supabase/functions/mcp/index.ts`, which is deployed as a Supabase Edge Function.

- **Any edit under `src/lib/mcp/` changes the public endpoint** on its next deploy. After a build, check
  `git status`: the generated file should only change when the MCP source did.
- Relative imports are inlined. Bare and alias imports (`@/…`) are rewritten to `npm:` specifiers and would
  break the deployed function, so MCP code uses relative imports only.
- esbuild keeps every value a module touches, so filtering at runtime does not keep data out of the deployed
  source. Data that must not be public must not be imported at all.

## Content and the website bundle

Vite ships every value in a module the site imports, whether or not it is rendered. Public content lives in
`src/content` and is imported through `@/content`. Content review files are kept outside the repository; the unit
tests that need them are skipped when they are absent, so a public clone runs the remaining tests.

**Content rules enforced by `npm test`** (`src/content/v2-content.test.ts`): every cross-reference resolves;
the AI Receptionist and VIVIFY Connect are labelled pilot; printing is partner-optional and in no package;
no prices, ranking guarantees, star-rating promises or invented social proof; every demo carries a
simulation note and uses fictional 555-01xx numbers; every listed tool appears in a real project stack;
homepage-featured projects are confirmed; site UI never hard-codes links.

## Where things live

| Concern                                                                              | Location                                                                  |
| ------------------------------------------------------------------------------------ | ------------------------------------------------------------------------- |

`src/components/vivify/media.ts` is still used for portfolio images.

## Static prerendering

`npm run build:prerender` renders all sitemap routes to static HTML and writes `dist/404.html`. `src/main.tsx`
hydrates when `#root` already holds server HTML and renders normally otherwise, so the same bundle works for both
builds. Per-route titles, descriptions, canonical URLs and `noindex` flags come from one table
(`src/lib/route-meta.ts`) used by the browser and by the server render. `scripts/serve-static.mjs` emulates
clean-URL static hosting with a real 404 status for local checks. See `docs/launch/prerender.md`.

## Contact form

`api/contact.ts` (Vercel Function) wraps `src/lib/contact-handler.ts`. The site shows "Message sent" only when the
server confirms the email provider accepted the message. Without credentials the endpoint answers
`503 not_configured` and the site offers an email fallback. See `docs/launch/contact-form.md`.
